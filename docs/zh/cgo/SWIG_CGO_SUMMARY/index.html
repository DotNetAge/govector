    🎯 核心内容概览¶

    1. 架构设计¶

    ┌─────────────────────────────────────┐
│      应用层 (Python/C++/Java)        │
├─────────────────────────────────────┤
│      SWIG 生成的包装层               │
├─────────────────────────────────────┤
│      CGO 桥接层 (C 接口)             │
│    govector_c.h / govector_c.go    │
├─────────────────────────────────────┤
│      GoVector 核心层 (Go)            │
│   Collection / Storage / Index     │
└─────────────────────────────────────┘

    2. API 接口¶

    存储引擎 (3 个函数)¶

    • govector_storage_new() - 创建存储
    • govector_storage_close() - 关闭存储
    • govector_storage_free() - 释放资源

    集合管理 (5 个函数)¶

    • govector_collection_create() - 创建集合
    • govector_collection_load() - 加载集合
    • govector_collection_drop() - 删除集合
    • govector_collection_free() - 释放句柄
    • govector_collection_count() - 获取点数

    点操作 (3 个函数)¶

    • govector_collection_upsert() - 插入/更新
    • govector_collection_search() - 相似度搜索
    • govector_collection_delete() - 删除点

    内存管理 (3 个函数)¶

    • govector_points_free() - 释放点数组
    • govector_scored_points_free() - 释放搜索结果
    • govector_error_free() - 释放错误信息

    总计: 14 个核心 API 函数

    3. 数据类型¶

    枚举类型¶

    • DistanceType - 距离度量（Cosine/Euclidean/Dot）
    • GovectorError - 错误码（8 种错误类型）

    结构体¶

    • HNSWParams - HNSW 参数配置
    • PointStruct - 向量点数据结构
    • ScoredPoint - 搜索结果数据结构
    • ErrorInfo - 错误信息结构

    句柄类型¶

    • StorageHandle - 存储句柄
    • CollectionHandle - 集合句柄

    🚀 使用流程¶

    步骤 1: 环境准备¶

    # 安装 SWIG
brew install swig  # macOS
sudo apt-get install swig  # Ubuntu

# 验证安装
swig -version
go version
gcc --version

    步骤 2: 构建绑定¶

    cd govector/capi

# 一键构建（推荐）
./build.sh all

# 或单独构建
./build.sh python    # Python 绑定
./build.sh java      # Java 绑定
./build.sh csharp    # C# 绑定

    步骤 3: 运行示例¶

    # Python 演示
python3 examples/demo.py

# C++ 示例（需要编译）
g++ -std=c++11 examples/cpp_example.cpp -L. -lgovector_c -o cpp_example
./cpp_example

    步骤 4: 开发应用¶

    import govector

# 创建客户端
client = VectorDatabaseClient("my.db")
client.connect()

# 创建集合
client.create_collection("my_col", vector_dim=128)

# 搜索
results = client.search("my_col", query_vector, top_k=10)

# 清理
client.disconnect()

    ⚠️ 重要注意事项¶

    内存管理（❗至关重要）¶

    三大原则： 1. 谁分配，谁释放 

    // C 分配的内存由 C 释放
ScoredPoint* results = malloc(...);
govector_scored_points_free(results, count);

    1. 及时释放所有资源 

      # ✓ 正确
handle = create_something()
try:
    use(handle)
finally:
    free(handle)

    2. 避免跨语言传递指针 

      // ✗ 错误：不要将 Go 指针传递给 C 长期保存
// ✓ 正确：使用 C.CString 并手动释放

    错误处理（❗必须检查）¶

    # ✓ 正确模式
error = ErrorInfo()
result = function(error)
if not result:
    print(f"Error: {error.message}")
    handle_error()

# ✗ 错误模式
result = function(None)  # 不检查返回值

    并发安全（❗需要保护）¶

    # ✗ 不安全：多线程共享句柄
thread1: client.search(...)
thread2: client.search(...)

# ✓ 安全：使用锁保护
with lock:
    client.search(...)

    🎓 最佳实践总结¶

    ✅ 必做清单¶

    • [x] 总是检查返回值和错误
    • [x] 及时释放所有资源（句柄、内存）
    • [x] 使用批量操作减少 CGO 调用
    • [x] 在多线程环境中使用锁保护
    • [x] 使用工具检测内存泄漏

    ❌ 禁止清单¶

    • [ ] 不要忽略错误返回值
    • [ ] 不要忘记释放 C 内存
    • [ ] 不要频繁进行 CGO 调用
    • [ ] 不要在多个线程中共享未保护的句柄
    • [ ] 不要传递 Go 指针给 C 长期保存

    📊 性能对比¶

    调用方式性能¶

    方式 相对延迟 相对吞吐量 推荐度
    直接 Go 调用 1x 1x ⭐⭐⭐⭐⭐
    CGO 批量调用 2x 0.5x ⭐⭐⭐⭐
    CGO 单次调用 10x 0.1x ⭐⭐
    HTTP API 100x 0.01x ⭐

    优化建议¶

    1. 优先批量操作 - 减少 CGO 调用次数
    2. 复用连接和句柄 - 避免频繁创建/销毁
    3. 零拷贝优化 - 高级场景使用 unsafe.Pointer

    🔧 故障排除速查¶

    常见错误及解决¶

    错误 原因 解决方案
    swig: command not found 未安装 SWIG brew install swig
    Python.h: No such file 缺少 Python 头文件 apt-get install python3-dev
    Segmentation Fault 内存访问错误 使用 gdb 调试
    Memory Leak 未释放内存 使用 valgrind 检测

    调试工具¶

    # GDB 调试
gdb ./program
(gdb) run
(gdb) bt

# Valgrind 内存检测
valgrind --leak-check=full ./program

# Go Race Detector
go build -race -buildmode=c-archive
