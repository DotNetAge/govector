    GoVector CGO 隔离架构 - 快速指南¶

    🎯 核心问题¶

    问题：如何在不污染 core 包的前提下，为 GoVector 添加 SWIG/CGO 支持？

    答案：使用独立适配层架构，将 CGO 代码完全隔离在 capi 子包中。

    📐 架构图解¶

    ┌─────────────────────────────────────────┐
│         外部应用 (Python/C++/Java)       │
└────────────────┬────────────────────────┘
                 │ 调用
                 ▼
┌─────────────────────────────────────────┐
│   capi/          CGO/SWIG 适配层         │
│   - govector_c.h   (C 头文件)            │
│   - govector_c.go  (Go 导出，import "C") │
│   - govector.i     (SWIG 接口)           │
└────────────────┬────────────────────────┘
                 │ 调用（纯 Go）
                 ▼
┌─────────────────────────────────────────┐
│   core/          纯 Go 核心              │
│   - collection.go  (无 import "C")      │
│   - storage.go     (无 import "C")      │
│   - models.go      (无 import "C")      │
│   - index.go       (无 import "C")      │
└─────────────────────────────────────────┘

    ✅ 三大设计原则¶

    原则 1: Core 包必须纯净¶

    ❌ 禁止： 

    // core/collection.go
package core

import "C"  // ❌ 绝对禁止！

    ✅ 正确： 

    // core/collection.go
package core

import (
    "fmt"
    "sync"
)

// ✅ 纯 Go 实现
type Collection struct {
    // ...
}

    原则 2: Capi 包专用适配¶

    // capi/govector_c.go
package capi

/*
#include "govector_c.h"
*/
import "C"  // ✅ 只在适配层使用

import (
    "github.com/DotNetAge/govector/core"  // ✅ 调用核心包
)

//export govector_collection_create
func govector_collection_create(...) C.CollectionHandle {
    // ✅ 调用核心包功能
    col, _ := core.NewCollection(...)
    return wrapHandle(col)
}

    原则 3: 单向依赖¶

    ✅ 允许：capi → core
❌ 禁止：core → capi

    🚀 快速上手¶

    场景 1: 纯 Go 应用（无需 CGO）¶

    如果您是 Go 开发者，直接使用 core 包：

    package main

import (
    "github.com/DotNetAge/govector/core"
)

func main() {
    // ✅ 直接使用纯 Go API
    col := core.NewCollection("my_col", 128, core.Cosine, nil, true)

    points := []core.PointStruct{
        {ID: "1", Vector: []float32{0.1, 0.2, /* ... */}},
    }

    col.Upsert(points)

    results, _ := col.Search(queryVector, nil, 10)

    // 编译无需 CGO
    // go build myapp.go
}

    优点： - ✅ 编译快速，无需 CGO 环境 - ✅ 部署简单，纯 Go 二进制 - ✅ 类型安全，完整的 Go 类型系统

    场景 2: Python 应用（使用 CGO）¶

    如果您需要从 Python 调用 GoVector：

    步骤 1: 构建 CGO 组件¶

    cd govector/capi
./build.sh python

    步骤 2: 在 Python 中使用¶

    #!/usr/bin/env python3
import govector  # 导入 SWIG 生成的模块

# 初始化
error = govector.ErrorInfo()
storage = govector.govector_storage_new("test.db", error)

# 创建集合
params = govector.HNSWParams()
params.m = 16
collection = govector.govector_collection_create(
    "my_col", 128, govector.DISTANCE_COSINE,
    True, params, storage, error
)

# 搜索
results = govector.govector_collection_search(
    collection, query_vector, len(query_vector), 10, ...
)

    底层原理： 

    Python 代码
    ↓
SWIG 包装层（自动生）
    ↓
CGO 桥接层（capi/govector_c.go）
    ↓
纯 Go 核心（core/collection.go）

    场景 3: C++ 应用（使用 CGO）¶

    #include "govector_c.h"

int main() {
    // 通过 C API 调用
    ErrorInfo error;
    StorageHandle storage = govector_storage_new("test.db", &error);

    HNSWParams params = {16, 200, 50, 2};
    CollectionHandle col = govector_collection_create(
        "my_col", 128, DISTANCE_COSINE,
        true, params, storage, &error
    );

    // ... 使用集合

    govector_collection_free(col);
    govector_storage_free(storage);

    return 0;
}

    编译： 

    g++ -std=c++11 myapp.cpp -L/path/to/capi -lgovector_c -o myapp

    🔧 构建命令对比¶

    纯 Go 构建（无需 CGO）¶

    # 构建 core 包
go build ./core                    # ✅ 快速，无 CGO

# 构建 API 服务
go build ./api                     # ✅ 快速，无 CGO

# 构建 CLI
go build ./cmd/govector            # ✅ 快速，无 CGO

# 运行测试
go test ./core                     # ✅ 快速，无 CGO

    CGO 构建（需要 SWIG 环境）¶

    # 进入 capi 目录
cd govector/capi

# 生成 SWIG 包装
swig -cgo -python -py3 -o govector_wrap.cxx govector.i

# 构建 Go 静态库
go build -buildmode=c-archive -o libgovector_c.a .

# 编译 Python 模块
g++ -fPIC -shared govector_wrap.cxx -o _govector.so \
    $(python3-config --includes) \
    -L. -lgovector_c

    📊 性能对比¶

    使用方式 延迟 吞吐量 适用场景
    Go 直接调用 core 1x 1x Go 应用内部 ⭐⭐⭐⭐⭐
    CGO 批量调用 2-5x 0.5x Python/C++ 应用 ⭐⭐⭐⭐
    CGO 单次调用 10-20x 0.1x 低频操作 ⭐⭐
    HTTP API 100x+ 0.01x 远程服务 ⭐

    优化建议： 1. Go 应用优先使用 core 包 2. 跨语言使用批量操作减少调用次数 3. 关键路径避免 CGO

    ⚠️ 常见错误¶

    错误 1: 在 core 包中使用 CGO¶

    ❌ 错误： 

    // core/collection.go
package core
import "C"  // ❌ 污染核心包！

    ✅ 正确： 

    // core/collection.go
package core
// ✅ 纯 Go，无 import "C"

// capi/govector_c.go
package capi
import "C"  // ✅ 只在适配层

    错误 2: 循环依赖¶

    ❌ 错误： 

    // core/storage.go
package core
import "github.com/DotNetAge/govector/capi"  // ❌ 循环依赖！

    ✅ 正确： 

    // core/storage.go
package core
// ✅ 无外部依赖

// capi/govector_c.go
package capi
import "github.com/DotNetAge/govector/core"  // ✅ 单向依赖

    错误 3: C 类型泄漏¶

    ❌ 错误： 

    // core/models.go
package core
type PointStruct struct {
    Vector *C.float  // ❌ C 类型泄漏到核心包
}

    ✅ 正确： 

    // core/models.go
package core
type PointStruct struct {
    Vector []float32  // ✅ 纯 Go 类型
}

// capi/govector_c.go
package capi
func convertPoint(cPoint *C.PointStruct) core.PointStruct {
    // ✅ 在适配层转换
    return core.PointStruct{
        Vector: cFloatSliceToGo(cPoint.vector, cPoint.dim),
    }
}

    🎯 决策检查清单¶

    在开发时，使用以下清单确保架构纯净：

    Core 包检查¶

    • [ ] 没有 import "C"
    • [ ] 没有使用 C.xxx 类型
    • [ ] 没有使用 unsafe.Pointer 进行 CGO 操作
    • [ ] 可以独立编译（go build ./core）
    • [ ] 测试无需 CGO（go test ./core）

    Capi 包检查¶

    • [ ] 所有 CGO 代码集中在此
    • [ ] 只依赖 core 包，不反向依赖
    • [ ] 负责所有类型转换
    • [ ] 提供清晰的错误处理
    • [ ] 有独立的测试

    整体架构检查¶

    • [ ] core 不依赖 capi
    • [ ] capi 可以依赖 core
    • [ ] 无循环依赖
    • [ ] 构建脚本清晰分离

    🎉 总结¶

    通过本架构，我们实现了：

    ✅ Core 包纯净 - 无任何 CGO 污染
    ✅ Capi 包专用 - 所有 CGO 代码集中管理
    ✅ 单向依赖 - 清晰的依赖关系
    ✅ 灵活构建 - 可选择性构建 CGO 组件
    ✅ 多语言支持 - Python/C++/Java 等

    这种设计既保持了 Go 代码的纯洁性，又提供了跨语言集成的能力！
