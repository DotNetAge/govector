    Project Overview¶

    GoVector is a lightweight, embeddable vector database written in pure Go, positioned as "the SQLite of vectors". It targets local AI, desktop applications, and edge computing scenarios, providing a high-performance, Qdrant-compatible solution for vector storage and retrieval.

    🎯 Core Features¶

    • Pure Go & CGO-Free: Cross-compile to anywhere (Windows, macOS, Linux, edge devices) without messy C/C++ dependencies
    • Qdrant Compatible API: Drop-in replacement with the same REST API endpoints
    • High Performance: Optimized for single-node performance, supporting millions of vectors with sub-millisecond search latency
    • HNSW Indexing: Industrial-grade graph-based index for O(log N) search complexity, enabled by default
    • Persistent Storage: Uses BoltDB and Protocol Buffers for ultra-fast persistence, data survives restarts
    • Advanced Filtering: Support for payload filtering (Exact, Range, Prefix, Regex, Contains) just like Qdrant
    • SQ8 Quantization: Built-in 8-bit scalar quantization to reduce disk footprint for large-scale data
    • Dual Modes: Embedded library (zero network overhead) or standalone microservice with REST API
    • Unified CLI & TUI: Powerful command-line interface with interactive Terminal User Interface

    🏗️ Architecture¶

    GoVector adopts a layered design architecture:

    Layers¶

    1. API Layer: Provides Qdrant-compatible HTTP REST API endpoints
    2. Core Engine: Handles collection management, indexing, and business logic
    3. Storage Layer: Manages persistence using BoltDB and Protocol Buffers
    4. Quantization Layer: Optional SQ8 quantization for memory optimization

    Key Components¶

    • Collection: Encapsulates vector collections with fixed dimension and distance metric
    • HNSWIndex: Graph-based index for fast approximate nearest neighbor search
    • Storage: Local persistence with support for collection metadata and point operations
    • API Server: Exposes Qdrant-style REST interfaces
    • Models and Filters: Data structures for points, scores, and filtering
    • Quantization: SQ8 quantizer for vector compression

    🚀 How It Works¶

    Data Flow¶

    1. Write Path: Client → API Layer → Collection → Storage (persist) → Index (update)
    2. Read Path: Client → API Layer → Collection → Index (search) → Storage (retrieve metadata)

    Search Process¶

    1. Query Validation: Validate vector dimension and parameters
    2. Index Search: Use HNSW for approximate nearest neighbor search
    3. Filter Application: Apply payload filters to search results
    4. Score Calculation: Recalculate exact scores for filtered results
    5. Result Return: Return top K results to client

    Embedded Mode¶

    1. Initialize Storage: Create or open a BoltDB database file
    2. Create Collection: Define vector dimension, distance metric, and index type
    3. Upsert Points: Write vectors and metadata directly using Go structs
    4. Search: Execute similarity search with optional filtering
    5. Close Storage: Release resources when done

    ⚡ Performance¶

    Benchmark Results (128-dimensional vectors, Cosine distance, TopK=10)¶

    Index Scale (N) Build Time Latency (Avg) Throughput (QPS) Memory (Alloc)
    Flat 100K 186 ms 54.46 ms 18 QPS 59 MB
    HNSW 100K 20.9 s 0.08 ms 11,812 QPS 311 MB
    HNSW 1M 4m 17s 0.11 ms 8,709 QPS 3.32 GB

    Optimization Techniques¶

    • HNSW Parameter Tuning: Adjust M, EfConstruction, and EfSearch for optimal performance
    • Oversampling + Post-filtering: Balance accuracy and performance for filtered queries
    • SQ8 Quantization: Reduce disk usage for large-scale data
    • Dual-write Consistency: Ensure data integrity between storage and index

    🛠️ Use Cases¶

    • Local AI Applications: Run vector search directly in desktop or mobile apps
    • Edge Computing: Deploy on edge devices with limited resources
    • Embedded Systems: Integrate into existing Go applications without network overhead
    • Prototyping and Development: Rapidly test vector search ideas without complex infrastructure
    • Small to Medium Scale Deployments: Serve vector search for small to medium-sized applications

    • example/embedded: Embedded usage examples
